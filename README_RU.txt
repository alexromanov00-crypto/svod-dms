СВОД ДМС — публикация общей веб-версии (бесплатный старт)

В архиве:
- index.html — сам дашборд
- config.js — настройки подключения к Supabase
- supabase.sql — создание общей базы и открытого доступа для редактирования

ВАЖНО О ДОСТУПЕ
Любой человек, у которого есть URL сайта, сможет просматривать, добавлять, изменять и удалять данные. Вход и регистрация не требуются. Не размещайте в этой таблице конфиденциальные сведения. Публичный anon key предназначен для браузера; service_role key использовать нельзя.

ШАГ 1. Создать общую базу Supabase
1. Откройте https://supabase.com/ и зарегистрируйтесь.
2. Нажмите New project.
3. Название: svod-dms. Выберите пароль базы данных и сохраните его у себя. Регион — ближайший доступный.
4. После создания проекта откройте SQL Editor -> New query.
5. Откройте файл supabase.sql из этого архива, скопируйте весь текст в окно SQL Editor и нажмите Run.
6. Откройте Project Settings -> API (или Data API / API Keys в новом интерфейсе).
7. Скопируйте Project URL и публичный anon / publishable key.
8. Откройте config.js и замените два значения-заглушки на скопированные значения. Кавычки оставьте.

ШАГ 2. Опубликовать сайт на Vercel
1. Откройте https://vercel.com/ и войдите через GitHub (если аккаунта GitHub нет — создайте на https://github.com/).
2. Создайте новый GitHub repository с названием svod-dms.
3. Загрузите в корень репозитория три файла: index.html, config.js, README_RU.txt (supabase.sql можно тоже загрузить, но он не нужен сайту).
   Самый простой способ: на GitHub нажать Add file -> Upload files.
4. На Vercel нажмите Add New -> Project и импортируйте репозиторий svod-dms.
5. Нажмите Deploy. Сборка не требуется — это статический сайт.
6. Vercel выдаст адрес вида https://svod-dms.vercel.app. Его можно отправить всем участникам.

ПРОВЕРКА
1. Откройте ссылку в двух разных браузерах/устройствах.
2. Измените поле в одном окне.
3. Изменение должно автоматически появиться во втором.

ОГРАНИЧЕНИЯ ТЕКУЩЕЙ ВЕРСИИ
- Данные общие для всех посетителей ссылки; авторизации и разграничения прав нет.
- Если два человека одновременно меняют один и тот же объект, последнее сохранение может перезаписать более раннее. Для обычной совместной работы лучше не редактировать одну строку одновременно.
- Для особо важных данных следует настроить резервное копирование Supabase.
- Бесплатные тарифы имеют лимиты использования и могут менять условия.
